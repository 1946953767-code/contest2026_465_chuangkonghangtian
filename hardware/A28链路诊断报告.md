# A28 链路诊断报告（最终版 · 已修复并通过验证）

> **结论：链路已完全打通，双向零丢包。**
> 根因是 **MD0/MD1 被接成 `1,1`（休眠配置模式），无线从头到尾没打开过**。
> 改接 GND（`0,0`）后立即恢复。模块本体自始至终完好无损。

## 二、根因：MD0/MD1 电平接反（手册工作状态表，第 7 页）

| 工作状态 | MD0 | MD1 | 说明 |
|---|---|---|---|
| **半双工工作状态** | **0** | **0** | 串口打开，**无线打开**，半双工传输 |
| 全双工工作状态 | 0 | 1 | 串口打开，**无线打开**，全双工传输 |
| 全双工工作状态 | 1 | 0 | 串口打开，**无线打开**，全双工传输 |
| **休眠配置工作状态** | **1** | **1** | **模块进入休眠状态，仅能通过串口配置** |

### 致命陷阱：MD0/MD1 是「极弱上拉」（手册第 6 页）
**悬空 = 高电平 = `1,1` = 配置模式。**
所以模块**必须被主动拉低**才能进正常传输状态 —— 之前悬空时和接 3v3 时
行为完全一样（都回 `ERROR`），就是因为两种接法都等于 `1,1`。

### 修复（手册 7.2.2「半双工传输」三条设置）
1. `MD0 = 0，MD1 = 0` ← **只需改这一条**
2. 收发地址相同 → 都是 `0x1234`（出厂默认）✅ 本来就满足
3. 收发信道相同 → 都是 `0x00`（出厂默认）✅ 本来就满足

**改完断电重上电即可。两台模块都要改。**

## 四、代码改动（ESP32 端，三处）

全部在 `hardware/esp32/central_tx.py`。**P4X 地面站固件一个字未改。**

### ① 链路状态不再说谎
`poll_lora_cmd()` 原来对**任何**收到的行都 `cmd_count += 1`，
导致模块吐的 `ERROR` 被当成"地面站下发的命令"（实测 80 秒凭空涨 36 个假命令）。

现在**只认 `B:` / `S:` 两种真实前缀**，其余归入新增的 `junk=` 计数，
并在 `STAT` 后打印噪声样本：

```
STAT ... cmd=0 junk=19 ...
JUNK 19 行 样本=['ERROR', 'ERROR', ...]
```

**一眼就能看出"没收到真命令，只在收模块报错"。**

### ② 接收行缓冲（修掉拆包假噪声）
原来按每次 `read()` 的边界切分命令行，一条命令被拆成两半就变成两条"噪声"
（实测 90 秒凭空涨 10 条 junk）。现在改为攒到 `\n` 才算一条完整命令，
并加了 512 字节上限防止缓冲无限增长。

### ③ 链路字段 `L` 解绑开关、改用被动判据
- 收到**真实命令**即视为"地面端在线" → 更新 `last_peer_ms` / `link_ever_ok`。
  这是**纯被动观测**：不发探测包、不抢半双工信道，
  比当年那套主动探测可靠得多（而且箭载端根本没有主动探测代码）。
- `full["L"]` **不再受 `LINK_MONITOR` 开关限制**，始终上报：
  `1`=最近听到过地面端 / `0`=曾经听到过但现在没声了 / `-1`=从未听到。
- 新增 `LINK_REPORT_MS = 300000`（5 分钟）作为 `L` 的新鲜度窗口。
  **不能用 60 秒**：P4 的兜底 PING 是"每 6000 个主循环 tick"，
  主循环被 LCD 刷屏拖慢后真实间隔可超 2 分钟，用 60 秒会误报断链。
- `LINK_MONITOR` 保持 `False`，只留给"链路告警音"（避免误报乱叫）。

## 五、A28 二进制配置协议（手册第六章，备查）

**注意：配置命令是二进制，不是 ASCII 的 `AT` 指令。**
模块根本没有 AT 指令集 —— 这是最初 28 种 ASCII 输入全部被拒的原因。

| 命令 | 功能 | 应答 |
|---|---|---|
| `C0 ADDH ADDL SPEED CHAN OPTION` | 设置参数（掉电保存） | `OK` / `ERROR` |
| `C2 ADDH ADDL SPEED CHAN OPTION` | 设置参数（掉电不保存） | `OK` / `ERROR` |
| `C1 C1 C1` | 读配置参数 | `C0` + 5 字节参数 |
| `C3 C3 C3` | 读硬件版本号 | `A28-T2G4A12D1a-V9.0` |
| `F3 F3 F3` | 读软件版本号 | `A28-T2G4A12D1a-V9.02` |
| `C4 C4 C4` | 复位模块 | `OK` |
| `C9 C9 C9` | 恢复出厂默认 | `OK` |
| `AF AF 73 00 AF F3` | 读当前数据 RSSI | RSSI 绝对值 |
| `AF AF 74 00 AF F4` | 读环境 RSSI | RSSI 绝对值 |

**`ERROR` 含义**：配置失败，原配置参数未被更改（只有 `C0`/`C2` 会回 `OK`/`ERROR`）。

**参数寄存器**
- `ADDH`/`ADDL`：模块地址，出厂 `0x12`/`0x34`
- `SPEED[7:6]` 校验：`00`=8N1(默认) `01`=8O1 `10`=8E1
- `SPEED[5:3]` 波特率：`000`~`111` = 1200/2400/4800/**9600(默认)**/19200/38400/57600/115200
- `SPEED[2:0]` 空速：`000`=空速0(默认)
- `CHAN`：信道，出厂 `0x00` = 2400MHz（FLRC: `2400+2*CHAN`）
- `OPTION[7]` 调制：0=FLRC(默认) 1=LoRa
- `OPTION[6]` 连续传输：0=非连续(默认) 1=连续(空速自适应)
- `OPTION[1:0]` 发射功率：`11`=12dBm(默认)

**关于"波特率哪个都可以"**：手册原文是「串口有 8 种常用的波特率可供选择，
支持的波特率范围 1200~115200」。是**可选范围**，不是任意值。
所谓"自适应"指的是**空中速率**（`OPTION[6]`），不是串口波特率。

**供电**：手册注明「输入电源纹波控制在 100mV 以内，可提供瞬间脉冲电流 200mA 以上」。
3.3V 可工作，但建议并 100µF 以上电容保证瞬态。

## 六、下一步可选升级：改全双工

当前 `MD0=0, MD1=0` 是**半双工**，固件为迁就它每 2 秒留 1 秒纯接收窗口，
**这期间遥测停发**（实测发送 2.14 包/秒，而设计值 4.5 包/秒，
`listen=` 计数和注释里的"丢包约 8%"都源于此）。

改成**全双工**（`MD0=0, MD1=1` 或 `MD0=1, MD1=0`，手册 7.2.3）后：
- **listen 窗口可整个删掉** → 遥测真连续，速率翻倍
- 按键命令**随时可下发**，不用等窗口，延迟从最坏 2 秒降到即时

代价：要改 `central_tx.py` 主循环时序。**建议链路稳定运行一段时间后再动。**

## 七、踩过的弯路（记录下来避免重犯）

| 弯路 | 真相 |
|---|---|
| 怀疑 ESP32 TX/RX 接反，软件对调 | 对调后**连收都收不到**，反而证明原接线是对的，已还原 |
| 以为 `cmd=` 递增说明"地面站→ESP32 通了" | 计数器对任何行都自增，那 36 个"命令"全是 `ERROR` 字符 |
| 以为是串口噪声 | 噪声不会那么整齐；静止测试证明是**按行的应答**（空闲时 0 条） |
| 以为是自适应波特率 | 灌 `0x55`/`0xAA` 同步头无效；模块串口固定在配置模式的 9600 |
| 以为是 ASCII AT 模块，穷举 28 种输入 | 模块**根本不用 AT 指令集**，用的是二进制 `0xC0/0xC1/0xC3/0xF3` 帧 |
| 以为 MD0/MD1 接 3v3 是"拉高使能" | **恰恰相反**，`1,1` 正是配置模式，必须拉**低** |
| 以为悬空 = 未定义 | 极弱上拉 → 悬空 = 高 = 配置模式，**必须主动拉低** |
